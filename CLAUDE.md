# Merkis.app — project guide for Claude

> Read this first. It is the source of truth for how the project is built, why, and what already went wrong once.
> **Keep it current:** every change that alters behaviour, structure, env vars, design rules or the version MUST update this file in the same change (see "Maintaining this file"). Keep it dense — it is loaded every session, so every line costs tokens.

## What it is
Mērķis = Latvian for "goal". A minimal planner web app, live at **https://merkis.app**. Current version: **v1.8** (`frontend/VERSION`). Owner: Ralfs (GitHub `RalfsXP/1`). Landing, auth, and the signed-in planner: top pill nav (desktop) / one morphing menu button (phones), Overview dashboard (/home), Calendar (Month + Week views), Events (once / weekly / monthly / yearly, countdowns, badges, shown in the calendar), Goals page with Day/Week/Month/Year/Custom tabs (priorities, recurrence, completion per occurrence, time left, custom badges), Sign up + log in, Guide (v1.6.4; step-by-step help with real screenshots), Settings, Site health (hidden from the menus since v1.6.3, still at /health; admins see internals + can run migrations), Whiteboards (Fabric.js; hidden from the menus since v1.6, still at /whiteboards), Music prototype (/music, public, in no menu: lyric snippet → songs + 30 s previews). **English only since v1.6.3** (Latvian strings kept, switch hidden).

|---|---|---|
| Frontend | Vue 3 + Vue Router + Vite (plain JS, `<script setup>`) | Vercel project **merkis** (root `frontend/`) → merkis.app |
| Backend | Laravel 13, PHP 8.4, Sanctum (cookie/session SPA auth) | Vercel project **planner-api** (root `backend/`, `vercel-php@0.8.0`, **region `dub1`** = next to Supabase) → `planner-api-ralfs.vercel.app` |
| DB | PostgreSQL | Supabase, project ref `duudrkutiojibyxidaqt`, eu-west-1, **session pooler** (port 5432; direct conn is IPv6-only → unusable from Vercel) |
| Email | Resend via SMTP (`smtp.resend.com:587`, user `resend`) | domain merkis.app verified (DKIM `resend._domainkey`, `send`, `rsend`) |
| Domain/DNS | merkis.app bought on Vercel (Vercel DNS) | team `ralfs` |

Request flow: browser → merkis.app → `frontend/vercel.json` rewrites `/api/*` and `/sanctum/*` to the backend → same origin, so no CORS and cookies just work. Never call the backend URL directly from the browser.

## Design rules (non-negotiable — the owner checks these)
- **One design (v1.8 "Paper & Pills")** — picked by the owner from 3 Dribbble-inspired options (design-options/ at the repo root, not deployed). Warm paper ground #f3efe7, white cards, ink #17171c pills, pastel colour-coding: Lavender #cbbcff, Mint #bdebc9, Peach #ffc9a6, Butter #ffe27a, Sky #c2e1ff, Rose #ffbfd0 (same in both themes, always ink text). Dark: #111113 ground, #1c1c20 cards, cream #f3efe7 pills with ink text. No glass, no mist, no backdrop blur (except the whiteboard bars).
  Look: big Bricolage display titles (`.page-title` 800, clamp 2.2–3rem, -0.045em) + chips; white rounded cards (radius 24–32, `--card-shadow`); ink primary pills; pastel tiles for highlights (Overview: today ring = lavender tile, streak = butter); done rows take a wash of their badge colour; tinted washes use `color-mix(… var(--wash|--wash-strong) …)` so dark mode stays dark (light 32/50 %, dark 14/24 %), controls on washes use `--wash-fill`.
  Tokens (main.css; `:root` = light, `[data-theme=dark]` overrides): `--bg --fg --muted --line --backdrop --surface --surface-2 --field --card-shadow --card-edge --float-shadow --dock (ink card) --accent/--on-accent --highlight/--on-highlight --link --soft --wash --wash-strong --wash-fill --flag-*`, pastels `--lav --mint --peach --butter --sky --rose`, `--ink --paper`, fonts `--font-display --font-body`, motion `--ease --spring --sheet-ease`. Components use tokens only, never raw hex (exceptions: #fff on ink surfaces).
- Other hues only for content: priority flags (`--flag-low` green / `--flag-high` amber / `--flag-important` red), user-picked badge colours (`SWATCHES`: Lavender, Mint, Peach, Butter, Sky, Rose, Violet #8b74ff, Ink + free `<input type=color>`) and whiteboard content. Category defaults: day Lavender/sun, week Sky/bolt, month Butter/star, year Mint/trophy, custom Peach/flag, event Rose/calendar. v1.6 preset hexes saved on goals/events/styles are shown as their pastel twin (`paletteColor()` / LEGACY map in lib/goals.js; stored data untouched). Badge text colour = `readableOn(hex)` (ink or white).
- **Icons: Heroicons only** (`@heroicons/vue`, 24/outline for UI, 20/solid for badges/flags). Badge icon list = `src/lib/icons.js` ⇄ `backend/config/goals.php` (keep in sync).
- Shared UI classes in main.css — use them, don't restyle per view: `.page(.narrow|.wide)` (centred in the shell), `.page-head` + `.page-title` + `.page-sub` + `.page-actions`, `.section-title`, `.section-label`, `.card` (+ `.card-head/.card-title`), `.chip(.quiet)`, `.list`, `.empty-state`, `.fold` (<details> with a rotating chevron), `.btn(-ghost|-primary|-lg)` (ghost = white pill), `.icon-btn(.bare)` (white disc / quiet fill inside cards), `.form-field/.form-label/.input`, `.segmented(.outline|.raised)` (chosen = ink pill; `.raised` = white track on the paper ground), `.switch-input` (checkbox as a toggle), `.display`. Motion: `.rise`, `.stagger` (children rise one after another), TransitionGroup `name="row"`, keyframes `rise/pop/draw` — entry animations use `backwards` fill (never `both`: it pins transforms). `prefers-reduced-motion` kills all of it. (AuthView has its own scoped `.field`.)
- Animations (owner asked for them, and for it to feel like a native app — phones especially): view changes rise in on desktop and slide sideways in menu order on phones (AppShell `view` / `view-next|prev`, <main> scroll reset after the old page leaves), nav pill slides between items (PillNav), every `.segmented` and the Goals tabs have a sliding ink pill (v-slide-pill), the phone menu morphs from the button (clip-path circle → card, bars → cross, staggered contents), the phone top bar swaps the wordmark for the page name on scroll, numbers count up (CountUp: rings, streak, totals, next-event days), lower sections rise in when scrolled to (v-reveal), ticks pop + draw only right after a real tick (`justTicked` in lib/goals.js), rings sweep and bars grow on load, Goals tabs slide the list in from the tab's side, month/week/date-picker pages follow the finger (`useSwipe`) then slide, titles turn, sheets slide with `--sheet-ease` and drag down like native sheets (follow finger, backdrop fades, flick closes, slides on from where released), theme switch cross-fades the whole page (View Transitions in lib/theme.js), landing cards float.
  Building blocks: `lib/directives.js` (v-slide-pill — options marked aria-pressed or a selector like `'.tab.active'`; v-reveal), `CountUp.vue`, `lib/motion.js` (expandIn/collapseOut via Web Animations: height + gap + fade; useSwipe; reducedMotion), `Expand.vue` (wrap a v-if'd element so it opens/closes instead of popping — forms' repeat/deadline/badge sections, errors, Settings accordion, DateField picker, HoldHint), `AnimatedList.vue` (a `.list`: staggered first show, then rows open/close their space and reorders glide — use it for every goal/event list), `Fold.vue` (collapsible "Completed"/"Past" group). Animate transform/opacity; height only through these helpers (never `transition: width/height`; bars slide with translateX). Measured with headless Chrome at 4× CPU slowdown: ~120 fps everywhere except one long frame while a heavy page first builds.
- Speed: `lib/intl.js` caches Intl formatters (a fresh one per row made lists stutter); AppShell preloads every page's code when idle (except the Fabric editor), so first visits slide in smoothly.
- Expired session: any signed-in API call answered 401/419 fires `merkis:signed-out` (lib/api.js) → user cleared (lib/auth.js) → AppShell replaces to /login; logout() treats 401/419 as success. (Local gotcha: re-seeding the demo user leaves the old session cookie — log out/in once.)
- Touch feel: every `:hover` rule sits inside `@media (hover: hover)` (on iPhone a tap otherwise leaves hover styles stuck); main.js adds an empty passive `touchstart` listener so iOS shows `:active` press feedback; `-webkit-tap-highlight-color: transparent`; index.html paints the ground colour before CSS loads (no white flash when the Home Screen app opens).
- Theme toggle lives top-right in every layout (landing, auth header, app top bar). LanguageSwitch sits next to it but renders nothing while `LOCALES` (lib/i18n.js) has one entry (`['en']`); Settings' language row likewise. Re-enable Latvian = add 'lv' back to `LOCALES`. **No clock** in the top bar.
- Check contrast when touching tokens: text on `--accent` / pastels must stay ≥4.5:1 (ink on every pastel, white on ink, ink on cream).
- **Fonts: Bricolage Grotesque (display: titles, big numbers, logo) + DM Sans (everything else)**, loaded in index.html. Buttons/inputs inherit (global rule).
- Light + dark mode: `data-theme` on `<html>`, set pre-paint by the inline script in `frontend/index.html` (default = system, light if unknown), toggled via `src/lib/theme.js` (also `syncThemeColor` → meta theme-color from `--bg`).
- **Minimal UI.** Owner dislikes extra text, feature claims for things that don't exist (no search/notifications/insights buttons), emojis, and "cards" around the logo. Don't add copy or decoration unasked.
- **Logo (v1.8):** the **sticker** — a lavender rounded square tilted −8° with an ink outline, an ink stroked "m" and a butter dot (fixed colours in both themes; `LogoMark.vue`, `animated` prop wobbles it). Lockup = sticker + "mērķis" in Bricolage 800 as live text (`AppLogo.vue`, size = parent font-size; `word` prop swaps the text — only /music uses it). Assets from `frontend/scripts/build-logo.mjs` (same sticker geometry — keep in sync with LogoMark): favicon = the sticker, home-screen icons = paper full-bleed + sticker, email/logo.png = sticker, brand/ lockups with Bricolage outlines. Regenerate, never hand-edit. Welcome email: paper page, white card, ink button, DM Sans/Bricolage.
- Mobile first-class (owner uses it mostly on phone, as a Home Screen web app): no text selection/callout on touch devices (html `user-select:none`, inputs re-enabled); no zoom (viewport `maximum-scale=1, user-scalable=no`, no `viewport-fit=cover` in tabs + global `touch-action: manipulation` + iOS `gesturestart` guard in main.js); body never scrolls (exact `--app-h`); in the app shell only `<main>` scrolls. Inputs ≥16px, safe-area padding, `overscroll-behavior: none`. Breakpoints: landing 640px; auth + app shell 860px (below: fixed opaque top bar (page name slides in once you scroll) + ONE round ink menu button bottom-right that morphs into the menu card (PhoneMenu; owner rejected the black bottom pill bar in v1.8); above: header row = logo + version chip, centred white pill nav with sliding ink pill (icons only 860–1099px), theme + avatar → Settings); calendar day panel beside the month only ≥1180px; sheets become dialogs ≥640px.

## DANGER / rules of engagement
- **`backend/.env` points at PRODUCTION Supabase.** Any `php artisan migrate|tinker|db:*` without DB overrides hits live data. Never run `db:show` (prints the DB URL incl. password). Destructive DB ops (truncate/drop/delete) → give the owner the SQL; don't run them.
- **Supabase Data API is locked (v1.4.2):** RLS on every `public` table with NO policies + anon/authenticated privileges revoked (also default privileges). Laravel connects as owner `postgres` (BYPASSRLS) so the app is unaffected. **Every migration that creates a table must call `App\Support\Rls::enable('table')`** (no-op on SQLite) — Site health check `db_rls` shows `RLS n/n`.
- Deploy order for schema changes: run `php artisan migrate` on Supabase **before** merging to `main` (new columns must exist before new code ships). Additive migrations only. v1.2 adds `goals`, `goal_completions`, `users.goal_styles`. From v1.2 on, Site health → "Run migrations" can do it from the live site — but only once code that runs without the new columns is deployed; for v1.2 itself run it from the terminal first.
- Git: owner commits & pushes himself. Work on a `version/x.y` branch from `main`; never commit/push unless asked. Exclude `.idea/` and `.claude/` from suggested `git add` (use `git add backend frontend README.md CLAUDE.md`).
- Merging to `main` = production deploy of both Vercel projects.

## Known gotchas (each cost real time once)
- Login "works" with wrong passwords even if session auth is broken (fails before touching the session). Real check: `POST https://merkis.app/api/login` **without** X-XSRF-TOKEN must return **419**; 422 means SANCTUM_STATEFUL_DOMAINS is wrong/missing → successful logins 500.
- vercel-php: `/api/*` routes 404 unless `api/index.php` fakes SCRIPT_NAME. Vercel FS is read-only except `/tmp`. `framework: null` required or Vercel treats backend as Vite (`dist` error).
- Vercel preview/deployment URLs sit behind Vercel Authentication; production domains are public.
- CSS: `filter` or `will-change: transform` on an ancestor becomes the containing block for `position:absolute` children (caused the jumping header during the auth swap). Auth header (`.form-top`) is therefore a direct child of `.auth-page`, not of a panel.
- `localhost` in the test browser can hold stale cookie-session cookies from earlier runs → bogus 401s. Test auth on `http://127.0.0.1:5173` for a clean jar.
- Claude desktop preview launcher can't access ~/Documents via bash/python (macOS TCC) → start local servers with Bash `run_in_background` instead of `.claude/launch.json` entries (only the `frontend` npm entry works).
- Browser-pane screenshots at emulated sizes sometimes render scaled/mid-transition; trust `getBoundingClientRect` measurements, wait ~1s after transitions.
- New DNS names: local router/ISP caches NXDOMAIN for up to 15 min; check with `dig @1.1.1.1`.
- Email clients: table layout + inline styles only; logo must be an absolute PNG URL (`FRONTEND_URL/email/logo.png`).
- GoalForm: type switching runs in `choosePeriod()` (the pill tap), never a `watch(form.period)` — loading a goal into the form changes the period too and a watcher wiped saved dates (custom end).
- Browser pane hidden ⇒ Vue leave transitions never finish (they wait on rAF): closed sheets stay in the DOM. In scripted checks read the LAST `.sheet`, or reload per case.
- AppShell's page `<Transition mode="out-in">` keeps the old view mounted while the route already changed: views read route params once at setup, or (GoalsView, keyed 'goals' for every period so tabs don't remount) follow them only while `route.name` is still theirs.
- Slow prod = check `x-vercel-id`: the middle region code is where the PHP function ran; it must be dub1 (Supabase is eu-west-1). Each request opens a fresh DB connection, so distance multiplies.
- Goal rows: desktop = check toggles, click edits; touch (`touchUI`) = tap anywhere toggles, hold edits (GoalItem, CalendarWeek goal rows + calendar strip badges via usePress). Don't add click-to-edit on touch.
- BottomSheet focuses `[autofocus]` inside it if present, else the dialog.
- **Home Screen web app viewport (iOS 26, measured on an iPhone 16 simulator):** `100%` / `100svh` / `documentElement.clientHeight` are the screen minus the status bar (793 of 852 pt), and after the keyboard has been open `100dvh`, `innerHeight`, fixed `inset: 0` and every fixed `bottom:` can shrink to that too and **stay shrunk** (scrollTo / re-setting the viewport meta don't fix it). Only `100lvh` stays the real screen. Hence `--app-h` (100dvh; `.standalone` → 100lvh): the shell, landing, login, LoadingScreen and BottomSheet are sized with it, and floating elements (PhoneMenu's layer is a fixed full-height box that stacks the button at its bottom with padding — no `bottom:`; AppVersion from the top) use `--app-h` (gap under the button = `--dock-gap` = max(14px, safe-area bottom)) — never use fixed `bottom:` or `inset: 0` for full-screen things. Re-verified for v1.8 in the iPhone 16 simulator: Home Screen app, log in with the keyboard, menu button + sheets stay on the real screen edge. iOS 26 draws the status bar dark in light mode by itself (no band needed). Test real-device behaviour in the iOS Simulator: Safari → Share → Add to Home Screen pointing at http://localhost:5173 (the simulator reaches the Mac's localhost); type slowly (wait between taps), screenshots lag ~1 s.
- iOS 26: a Safari tab with `viewport-fit=cover` lets the bottom toolbar cover sheets → no cover in tabs. Home Screen web apps get an edge-blur ramp over the top unless an opaque fixed box covers the top edge — v1.8's opaque paper top bar does exactly that (no ramp, no band). In standalone `--top-inset` = safe area + 14px so the header sits below the ramp (top bar, landing/auth headers use `var(--top-inset)`, never env(safe-area-inset-top) directly). `html` has an opaque background (Safari's fallback colour). theme-color is ignored by Safari 26.
- iPhone status-bar strip: in a Safari tab it belongs to Safari — it tints the page under it. v1.8: the phone top bar is **opaque `--bg`** (same as the ground, so it's invisible) + an `::after` gradient 22px lower (soft edge; scrolled content disappears under it). Opaque + no backdrop-filter/mask on `.topbar` also stops iOS 26's own top blur in the Home Screen app (that blur + ours looked like two bands). Never give the bar a tint or backdrop-filter. Left-side drawers always looked cut under it (rejected twice); a full-width solid bottom block was rejected. The black floating bottom pill bar (v1.8 draft) was rejected too. Keep: fixed top bar + one round menu button; no bottom bars.
- **iPhone Safari tab (iOS 26.5, iPhone 16, v1.6.3):** viewport = 695 pt (starts under the 59 pt status bar, ends above the 98 pt toolbar; lvh 735, safe areas 0); `viewport-fit=cover` does nothing in a tab (script or static meta); Safari paints both strips plain `--bg` and draws nothing of ours under the toolbar (with a flat paper ground that's seamless — v1.6's `--mist-edge` fades are gone). Tabs (`:root:not(.standalone)` + `(hover:none) and (pointer:coarse)`) lock the window scroll in the shell — `<main>`'s overflow counts toward document height, so the window could scroll and the keyboard left it shifted. These rules live in main.css: scoped `:global(:root:not(.standalone))` inside a media query was silently dropped by Vue — and so is a scoped
  `:global([data-theme='dark']) .x` anywhere (MusicView): for per-theme colours use a token that differs per theme (e.g. `--dock`).
- Whiteboard: Fabric needs `enablePointerEvents: true`; the surface needs its own `touch-action: none` (global is `manipulation`). Never rebuild `freeDrawingBrush` in a capture-phase pointerup — Fabric then finishes the stroke on an empty brush (a dot at 0,0). Fabric 7 default origin is centre.
- Every period (incl. 'custom') and 'event' needs an entry in BOTH `DEFAULT_STYLES` (src/lib/goals.js) and `config/goals.php` default_styles — a missing one makes `readableOn(undefined)` crash the render.
- A card's box-shadow inside an `overflow: auto` wrapper gets clipped at the sides and reads as a grey box under it (auth form on phones) — let the wrapper overflow or give it side padding.
- Browser pane hidden ⇒ screenshots fail. Fallback: headless Chrome over CDP (`--headless=new --remote-debugging-port`, Node's built-in WebSocket; own `--user-data-dir` in the scratchpad), Page.captureScreenshot. Vite listens on `localhost` only (127.0.0.1:5173 refuses).
- Dates: SQLite (tests) stores dates as text → bind query dates as `toDateString()`, never Carbon. JS week numbers: round the day diff (DST makes it an hour short).
- Browser pane: background-tab rendering is throttled → CSS transitions/screenshots lag seconds; verify via DOM/JS, not screenshots taken right after a click. For screenshots inject a temporary `*{transition:none!important}` style via javascript_tool (debug only), and use `zoom` to force a fresh capture.
